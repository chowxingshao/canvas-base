# Languages and route identities

Internationalization is off by default. Default content still lives in
`src/content/<collection>/en/`, and the complete UI dictionary lives in
`src/content/ui.json`. A single-language project needs no `src/i18n` directory.
Only the configured default locale receives routes when `features.i18n` is false.

To enable languages, set `features.i18n: true`, add language tags to
`i18n.locales`, and keep `language` equal to `i18n.defaultLocale`. Use valid
BCP 47 tags such as `en`, `ms`, `pt-BR`, or `zh-Hant` consistently in config,
content folders, and dictionary filenames. `pnpm configure:project` creates
optional `src/i18n/<locale>.json` dictionaries from the default dictionary when
i18n is enabled. They are clearly documented English fallback copy: translate
their values before launch rather than treating them as a translation.

The default language is unprefixed. Other languages use `/<locale>/` after
`base`: `/about/`, `/ms/about/`, or `/demo/ms/about/`. Home uses `/`, posts use
`/blog/<slug>/`, and projects use `/projects/<slug>/`. Enabled blog/project
indexes exist even with no entries. Disabling either feature removes its entry
and index records. `blog`, `projects`, and enabled locale tags are reserved page
slugs. Unknown content locales and duplicate published identities fail builds.
Astro i18n configuration is conditional and uses `prefixDefaultLocale: false`;
no Astro automatic fallback mapping or custom server middleware is configured.

`getRouteManifest()` is the build-process cache shared by page wrappers, SEO,
feeds, and discovery. `buildRouteManifest(entries, config, warn)` is also
available for isolated processing. Each record has a `kind`, `slug`, mounted
`path`, UI `locale`, `contentLocale`, `fallback`, optional source `entry`,
`canonicalPath`, and published `alternates`. Index records have `slug: ''` and
no entry. Optional-rest `[...index].astro` wrappers should pass
`params: { index: undefined }` for the index root. Never derive Astro route
parameters from the mounted URL: Astro applies `base` itself.

Translations share a collection and frontmatter slug. Missing or draft
translations use published default content, with one warning per identity and
requested language. A default draft cannot supply fallback content. Published
translations may exist without a published default and only receive their own
routes. Drafts and `not-found` are omitted from the manifest. Fallback records
canonicalize to the source route and are excluded from alternates. Sitemap
consumers must filter `fallback: true`. Index records are actual localized UI
routes and include all enabled locale indexes as alternates.

Set the document `lang` to the requested UI locale and the article `lang` to
`contentLocale`, including on fallback pages. Use `getUi(locale)` for UI copy.
Locale JSON overrides may omit keys: missing strings inherit default values
with one aggregated warning per locale per build. Extra keys, wrong shapes,
empty strings, and non-string leaf values fail validation. The default JSON
shape infers `UiStrings`; `resolveUiStrings(locale, overrides, warn)` exposes
that same validation independently of dictionary file loading.

`withBase` accepts internal paths, preserves asset extensions and query/fragment
suffixes, and does not reapply an existing base. `localePath` normalizes route
slashes and accepts unprefixed or already mounted locale URLs. Both use segment
boundaries, so `/demography/` is not confused with `/demo/`. Use manifest paths
for content links, especially when a content slug equals the base directory.

`localeDirection(locale)` uses `Intl.Locale` text direction and falls back to
maximized script detection when text-info APIs are unavailable. Apply `dir`
to the document; use logical CSS (`margin-inline`, `padding-inline`,
`inset-inline-start`, `text-align: start`) so RTL languages inherit the layout.
Choose self-hosted fonts with glyph coverage for each enabled script and test
mixed-direction text, punctuation, and numerals. Consumers should format dates,
numbers, and currencies with `Intl.DateTimeFormat` and `Intl.NumberFormat` using
the requested locale rather than concatenating formatted strings.

Astro routing details: [official internationalization guide](https://docs.astro.build/en/guides/internationalization/).

For release acceptance, build en/ms with missing translations and Arabic RTL fixtures, inspect source canonicals and `lang`/`dir`, and test long translated UI strings at 360/768/1280. Missing translations are explicitly reported fallback content; English dictionaries generated by setup are not approved translations. Choose an Arabic-covering self-hosted font before shipping Arabic content. See [quality evidence](quality-report.md).
